CHAPTER OVERVIEW

ทำไมต้องแปลงเป็นดิจิทัล?

ภาพจากกล้องเป็นสัญญาณต่อเนื่อง (analog) — คอมพิวเตอร์เก็บได้แค่ตัวเลข → ต้องแปลงด้วย 2 ขั้นตอน

ขั้นที่ 1 · Sampling

เก็บตัวอย่างตามตำแหน่ง (x, y) — เหมือนวางตารางทับภาพแล้วอ่านค่าที่จุดตัด

ขั้นที่ 2 · Quantization

ปัดค่าความเข้มให้เป็นระดับที่จำกัด — เช่น ระดับเทา 0–255

Pipeline: ภาพจริง → ดิจิทัล
1กล้อง/สัญญาณวิดีโอ (analog) — ค่าต่อเนื่อง
2Frame Grabber / Digitizer — อุปกรณ์แปลงสัญญาณ
3Sampling — เก็บตัวอย่างตำแหน่ง (spatial)
4Quantization — ปัดค่าความเข้ม (amplitude)
5ได้ภาพดิจิทัล — ตารางตัวเลขที่คอมพิวเตอร์ใช้ได้
ศัพท์ตำราต้อง digitize ทั้ง spatially (ตำแหน่ง) และ in amplitude (ค่าความเข้ม) — สองอย่างนี้คือ Sampling + Quantization

DIGITIZATION

f(x, y) — ดิจิไตซ์ 2 ทาง

ฟังก์ชันภาพ f(x, y) ต้องถูกทำเป็นดิจิทัลทั้ง 2 มิติ: ตำแหน่ง (space) และ ความเข้ม (amplitude)

ภาพ = กราฟ 3 มิติของความเข้ม

แกน x, y = ตำแหน่ง · แกน z = ค่าความเข้ม

ทางที่ 1 · Spatial (ตำแหน่ง)

แบ่งแกน x, y เป็นจุดจำกัด → ได้ "พิกเซล" — ทำโดย Sampling

ทางที่ 2 · Amplitude (ความเข้ม)

แบ่งค่าความเข้มเป็นระดับจำกัด → ทำโดย Quantization

เทคนิคสอบSampling → spatial (ตำแหน่ง) · Quantization → amplitude (ระดับเทา)

SAMPLING

Sampling — เก็บตัวอย่างตำแหน่ง

วางตาราง (grid) ทับภาพ แล้วอ่านค่าความเข้มที่จุดตัด — ระยะห่างของจุด = sampling rate

วางตาราง Sampling ทับภาพ

จุดตัดแต่ละจุด → กลายเป็น 1 พิกเซลของภาพดิจิทัล

Sampling Rate = ?

จำนวนตัวอย่างต่อพื้นที่ — สูง = เก็บถี่ = พิกเซลเยอะ = ละเอียด

ผลของ Sampling

กำหนด Spatial Resolution — ความละเอียดเชิงพื้นที่ของภาพดิจิทัล

เทคนิคสอบSampling rate → spatial resolution (จำนวนพิกเซล) — ไม่ใช่จำนวนสี

SAMPLING RATE

Sampling Rate — ละเอียด vs หยาบ

เก็บถี่แค่ไหน = ภาพละเอียดแค่ไหน — ลองเทียบ 3 ระดับ

Sampling สูง

พิกเซลเยอะ → รายละเอียดชัด (แต่ไฟล์ใหญ่)

Sampling กลาง

พอใช้ได้ รายละเอียดเริ่มหายบ้าง

Sampling ต่ำ

พิกเซลน้อย → เป็นบล็อก ๆ เห็นเป็นตารางชัด

จำแบบนี้Sampling สูง = ละเอียดแต่ใหญ่ · Sampling ต่ำ = เบาแต่หยาบ — โจทย์ถาม "spatial resolution" = เรื่อง Sampling

QUANTIZATION

Quantization — ระดับความเข้ม

ค่าความเข้มต่อเนื่อง → ปัดเป็นระดับที่จำกัด (grey levels) — กำหนดโดยบิตต่อพิกเซล

ตัวอย่าง: ระดับเทา 4 ระดับ (2 บิต)
3 (ขาว)
2 (เทาอ่อน)
1 (เทาเข้ม)
0 (ดำ)

ค่าความเข้มจริงทุกค่า → ถูกปัดให้อยู่ใน 4 ระดับนี้

ระดับเทา = 2^บิต

8 บิต = 256 ระดับ · 16 บิต = 65,536 ระดับ — ยิ่งเยอะยิ่งไล่สีเรียบเนียน

Quantization Level = ?

จำนวน grey levels ในภาพ — กำหนดโดยขั้นตอนนี้ (ไม่ใช่ Sampling)

เทคนิคสอบQuantization → grey levels · 8 บิต = 256 ระดับ

QUANTIZATION PROBLEM

False Contours — รอยหยักของระดับเทา

ระดับเทาน้อยเกินไป → บริเวณที่ควรไล่สีเรียบ กลายเป็นเส้นขั้นบันได

เปรียบเทียบ: ระดับเทาเยอะ vs น้อย

256 ระดับ — เรียบเนียน

6 ระดับ — เห็นขั้นบันไดชัด

เกิดจากอะไร?

Quantization ด้วย ระดับความเข้มไม่พอ (quantization level ต่ำเกินไป)

แก้ยังไง?

เพิ่มจำนวน grey levels (บิตต่อพิกเซล) — เช่น จาก 6 ระดับเป็น 256 ระดับ

เทคนิคสอบFalse Contours = รอยขั้นบันได = ระดับเทาน้อยไป (Quantization ไม่พอ)

QUANTIZATION EXAMPLE

ตัวอย่าง: ลด 256 → 16 ระดับ

โจทย์จาก PDF: ลดภาพจาก 256 ระดับเหลือ 16 ระดับ ด้วยสูตร q = (img // 16) * 16 + 7

โจทย์: img = [210, 219, 223, 108, 105, 99] 
import numpy as np
img = np.array([210, 219, 223, 108, 105, 99])
q = (img // 16) * 16 + 7
print(q)
# [215 215 215 103 103 103]
ก่อน[210, 219, 223] → หลังแปลง: [215, 215, 215]
ก่อน[108, 105, 99] → หลังแปลง: [103, 103, 103]

อ่านสูตรเป็นภาษาไทย

1. img // 16 = หาร 16 ปัดเศษทิ้ง (หาว่าอยู่ช่วงไหน)
2. × 16 = กลับมาเป็นค่าต้นช่วง
3. + 7 = ขยับไปกลางช่วง

16 ระดับ = 4 บิต

2^4 = 16 — เก็บ 4 บิตต่อพิกเซล แทน 8 บิต → ไฟล์เล็กลงครึ่งหนึ่ง

ที่มาเลข 160–255 มี 256 ค่า ÷ 16 ช่วง = ช่วงละ 16 ค่า → แต่ละช่วงแทนด้วยค่าเดียว

คำนวณด้วยมือ — 210 → 215

ทำทีละขั้นด้วยเครื่องคิดเลขธรรมดา — ใช้ได้กับทุกค่าที่เหลือ

และค่า: 108

BIT-PLANE

Bit-Plane คืออะไร — บิตต่อพิกเซล

พิกเซล 8 บิต = 8 "ชั้น" — ชั้นที่ 1 เก็บบิตที่ 0 ของทุกพิกเซล, ชั้นที่ 2 เก็บบิตที่ 1, …

บิต 7 6 5 4 3 2 1 0 — แต่ละตำแหน่ง = 1 ชั้น (plane)

8 ชั้นภาพขาวดำ

Bit-Plane แต่ละชั้นเป็นภาพ Binary (0/1) — รวม 8 ชั้นกลับคืนเป็นภาพต้นฉบับได้

น้ำหนักของบิต

บิต 7 (ซ้ายสุด) = 128 … บิต 0 (ขวาสุด) = 1 — ยิ่งซ้ายยิ่งสำคัญ

จำแบบนี้ภาพ 8 บิต = ภาพขาวดำ 8 ชั้นซ้อนกัน — แต่ละชั้นคือ bit plane

BIT-PLANE SLICING

Bit-Plane Slicing — (ex >> i) & 1

วิธีแยกบิต: เลื่อนบิตที่ต้องการมาล่างสุด แล้ว & 1 เพื่อตัดเอาเฉพาะบิตนั้น

โค้ดจาก PDF 
ex = np.array([255, 147, 55])
bit_plane = np.zeros((8, len(ex)))   # 8 แถว × 3 คอลัมน์

for i in range(8):
    bit_plane[i] = (ex >> i) & 1

print(bit_plane)
>> iเลื่อนบิตไปขวา i ตำแหน่ง — บิตที่ i ย้ายมาอยู่ล่างสุด
& 1ตัดเหลือเฉพาะบิตล่างสุด (0 หรือ 1)
วน 8 รอบi = 0..7 → ได้ครบทั้ง 8 บิต

ตัวอย่าง: ex = 147

147 = 10010011₂ — ลอง bit 4: 147 >> 4 = 9 (1001) → 9 & 1 = 1 ✓

ใช้ทำไม?

แยกภาพเป็นชั้น ๆ → รู้ว่าชั้นไหนสำคัญ (MSB) ชั้นไหนเก็บ noise (LSB) → บีบอัด/ซ่อนข้อมูล

เทคนิคสอบ(ex >> i) & 1 = ดึงบิตตำแหน่ง i · i = 0 คือบิตขวาสุด (LSB)

WORKED EXAMPLE

ตัวอย่างจริง — [255, 147, 55]

ผลลัพธ์จากโค้ดในสไลด์ก่อน — อ่านทีละแถว (bit 0 อยู่แถวล่างสุด)

255= 11111111 → ทุกบิตเป็น 1 (ขาวเต็ม)
147= 10010011 → บิต 7,6,3,1,0 เป็น 1
55= 00110111 → บิต 5,4,2,1,0 เป็น 1

MSB / LSB

อ่านตาราง Bit-Plane — MSB / LSB

ตารางน้ำหนักบิตจาก PDF — จดไว้ให้แม่น

Bitชื่อน้ำหนัก (2^n)เก็บข้อมูลแบบใด
Bit 7MSB2^7 = 128โครงสร้างหลัก (ภาพรวม)
Bit 6—2^6 = 64โครงสร้างรอง
Bit 5—2^5 = 32รายละเอียดปานกลาง
Bit 4—2^4 = 16รายละเอียดปานกลาง
Bit 3–0LSB2^3…2^0 = 8, 4, 2, 1รายละเอียดเล็ก + Noise
เทคนิคสอบMSB = Most Significant = bit 7 = 128 (สำคัญสุด) · LSB = Least Significant = bit 0 = 1 (สำคัญน้อยสุด)

MSB

Bit 7 (MSB) — น้ำหนัก 128

บิตที่ "หนัก" ที่สุด — มีผลต่อค่าพิกเซลมากที่สุด จึงเก็บโครงสร้างหลักของภาพ

พิสูจน์: เปิด-ปิดบิต 7
1พิกเซล 150 = 10010110₂
2ปิดบิต 7 (128): 150 − 128 = 22 — มืดลงทันที
3ปิดบิต 0 (1): 150 − 1 = 149 — แทบไม่ต่าง

บิต 7 เปลี่ยนค่าทีละ 128 → ภาพเปลี่ยนทั้งโทน

เห็นภาพยังไง?

Bit-plane 7 ออกมาเป็นภาพขาวดำที่ "เหมือนภาพต้นฉบับ" ที่สุด — เห็นโครงร่างชัด

ทำไมสำคัญ?

เก็บบิต 4–7 อย่างเดียวก็ยังเห็นภาพเกือบสมบูรณ์ → เป็นหลักการบีบอัด (สไลด์ 18)

เทคนิคสอบMSB = bit 7 = 128 = โครงสร้างหลักของภาพ

LSB

Bit 3–0 (LSB) — รายละเอียด + Noise

บิตน้ำหนักน้อย (8, 4, 2, 1) — เปลี่ยนแล้วภาพแทบไม่เปลี่ยน จึงเป็นที่อยู่ของรายละเอียดเล็ก ๆ และ noise

LSB = Noise

บิตล่างเปลี่ยนตาม noise ได้ง่าย — ภาพ bit-plane 0–3 จะดู "รำคาญตา" ไปหน่อย

LSB = ข้อมูลซ่อน

กลับกัน: เปลี่ยน LSB แล้วตามองไม่เห็น → เอาไว้ซ่อนข้อมูล (สไลด์ 19)

เทคนิคสอบLSB = bit 0 (น้ำหนัก 1) · เก็บรายละเอียดเล็ก + noise · ซ่อนข้อมูลได้

APPLICATION · COMPRESSION

Application 1 — Image Compression

MSB เก็บโครงสร้าง · LSB เก็บรายละเอียดเล็ก ๆ — ทิ้ง LSB ได้โดยภาพยังพอเห็น!

บีบอัด 50% ด้วย bit-plane
1เก็บบิต 4–7 (ครึ่งบน — โครงสร้างหลัก)
2ทิ้งบิต 0–3 (ครึ่งล่าง — รายละเอียดเล็ก/noise)
3เหลือข้อมูล 4/8 = 50% ของเดิม
ผลภาพยังพอเห็นโครงสร้างชัด แต่ไฟล์เล็กลงครึ่งหนึ่ง — trade-off ระหว่างคุณภาพกับขนาด

ทำไม 50%?

8 บิต ทิ้ง 4 บิตล่าง = เหลือครึ่งหนึ่งของข้อมูล — ลด bandwidth/พื้นที่จัดเก็บได้มาก

ข้อแลกเปลี่ยน

รายละเอียดละเอียด ๆ (พื้นผิว, ขอบเล็ก) หาย — เหมาะกับภาพที่เน้นโครงสร้าง

เทคนิคสอบCompression ด้วย bit-plane = เก็บ bit 4–7 ทิ้ง bit 0–3 → เหลือ 50%

APPLICATION · WATERMARK

Application 2 — Watermarking / Steganography

ซ่อนข้อมูลลับ/ลายน้ำในภาพ — ใช้ LSB ที่ตามองไม่เห็นการเปลี่ยนแปลง

ซ่อนบิตข้อมูลใน LSB
1พิกเซล 151 = 10010111₂ (LSB = 1)
2ซ่อนบิต 0: เปลี่ยน LSB เป็น 0 → 150
3ค่าเปลี่ยนแค่ 1/255 — ตาแยกไม่ออก!
4อ่านกลับ: เอา LSB ของทุกพิกเซลมารวมกัน = ข้อมูลที่ซ่อน

Watermark

ฝังลายน้ำ/ชื่อเจ้าของในภาพ — พิสูจน์ความเป็นเจ้าของภาพที่ถูกโจรกรรม

ซ่อนข้อความลับในภาพ — คนดูเห็นแค่ภาพปกติ แต่คนรู้วิธีอ่านได้ข้อมูล

เทคนิคสอบซ่อนข้อมูล = ใช้ LSB (bit 0) · เพราะเปลี่ยนแล้วตามองไม่เห็น

DOWNSAMPLING

Downsampling — ลดขนาดภาพ

ลด resolution ของภาพ — ตัวอย่าง: 1024×1024 → 512×512 → 256×256 (ลดลง 2, 4, 8, 16 เท่า)

ภาพลดขนาดต่อเนื่อง
1024×1024
↓
512×512
↓
256²

ขนาดลดลงเท่าไร?

11024 → 512 = ครึ่งหนึ่งทั้ง 2 ด้าน
2พิกเซล = ½ × ½ = ¼ ของเดิม
3ไฟล์/การคำนวณลด 75%
เทคนิคสอบลดครึ่งทั้ง 2 ด้าน = พิกเซลเหลือ ¼ (ไม่ใช่ ½!) — ระวังพลาดข้อนี้ประจำ

WHY DOWNSAMPLE

ทำไมต้อง Downsample? — 7 เหตุผล

เหตุผลหลัก ๆ จาก PDF — จำเป็นข้อ ๆ ได้เลย

1. เร็วขึ้น

Filtering, Edge Detection, Morphology ฯลฯ คิดต่อพิกเซล — พิกเซลน้อย = เร็วมาก

2. ลด Bandwidth

ส่งภาพผ่านเน็ตใช้ข้อมูลน้อยลง — เหมาะกับวิดีโอ/สตรีมมิง

3. ลด Noise

เฉลี่ยพิกเซลลง → noise ถูกกลบ/ลดลง

4. Image Pyramid

สร้างภาพหลายระดับ ใช้ใน Object Detection, Face Detection

5. หลาย Scale

SIFT, SURF, ORB, Optical Flow — ตรวจจับวัตถุหลายขนาด

6. ก่อนป้อน ML Model

โมเดลต้องการ input ขนาดคงที่ — ลดภาพให้พอดีก่อนป้อน

7. ประหยัดพื้นที่

เก็บ/สำรองภาพเล็ก ๆ หลายภาพแทนภาพใหญ่

8. ภาพรวมเร็ว ๆ

ดูภาพย่อ (thumbnail) ก่อนเลือกดูภาพเต็ม

จำแบบนี้Downsample = เร็วขึ้น · เบาขึ้น · ลด noise · pyramid · ML — เสียอย่างเดียวคือรายละเอียดลดลง

ชุดภาพ downsample ต่อเนื่องกัน — ใหญ่สุดอยู่ล่าง ซ้อนขึ้นไปจนเล็กสุด

1024²

ลดลงครึ่งหนึ่งทุกชั้น — 4 ชั้นจาก 1024 → 128

ทำไมต้องหลายขนาด?

วัตถุเล็กในภาพใหญ่ = วัตถุใหญ่ในภาพเล็ก — สแกนหลายระดับจับวัตถุได้ทุกขนาด

ใช้ในงานอะไร?

Object Detection · Face Detection · SIFT · SURF · ORB · Optical Flow

เทคนิคสอบPyramid = ภาพหลาย scale ซ้อนกัน · ใช้จับวัตถุหลายขนาด (SIFT/SURF/ORB)

2 ขั้นตอน

Sampling (เก็บตำแหน่ง) + Quantization (ปัดระดับเทา)

Sampling

กำหนด spatial resolution — เก็บถี่ = ละเอียด

Quantization

กำหนด grey levels — น้อยเกินไป = False Contours

Bit-Plane

แยกบิต 0–7 · MSB = โครงสร้าง · LSB = รายละเอียด+noise

Applications

Compression (เก็บบิต 4–7 = 50%) · Watermark (ซ่อนใน LSB)

Downsampling

1024→512 = ¼ พิกเซล · Image Pyramid ใช้ Object Detection

จำแบบนี้Sampling = ที่ไหน · Quantization = เท่าไร · q = (img//16)*16+7 · LSB ซ่อนข้อมูล · downsample ½×½ = ¼
