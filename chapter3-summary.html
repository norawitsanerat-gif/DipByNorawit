บทที่ 3 — Sampling, Quantization & Bit-Plane (จากภาพจริงเป็นภาพดิจิทัล)

2 ขั้นตอน: Sampling (ตำแหน่ง) + Quantization (ความเข้ม)
ระดับเทา = 2^บิต
q = (img // 16) × 16 + 7 (256 → 16 ระดับ)
บิต: MSB = bit 7 (128) · LSB = bit 0 (1)

1 · ทำไมต้องแปลงเป็นดิจิทัล — 2 ขั้นตอน

  • ภาพจากกล้อง = สัญญาณต่อเนื่อง (analog) แต่คอมพิวเตอร์เก็บได้แค่ตัวเลข → ต้องแปลง (digitize) ด้วย 2 ขั้นตอน
  • ขั้น 1 · Sampling — เก็บตัวอย่างตามตำแหน่ง (x, y) เหมือนวางตารางทับภาพแล้วอ่านค่าที่จุดตัด → แต่ละจุดกลายเป็น 1 พิกเซล
  • ขั้น 2 · Quantization — ปัดค่าความเข้ม (amplitude) ให้เป็นระดับจำกัด เช่น ระดับเทา 0–255
  • ศัพท์ตำรา: ต้อง digitize ทั้ง spatially (ตำแหน่ง = Sampling) และ in amplitude (ความเข้ม = Quantization)
  • Pipeline: กล้อง/สัญญาณวิดีโอ (analog) → Frame Grabber / Digitizer (อุปกรณ์แปลงสัญญาณ) → Sampling → Quantization → ภาพดิจิทัล (ตารางตัวเลข)

2 · Sampling — เก็บตัวอย่างตำแหน่ง

  • Sampling Rate = จำนวนตัวอย่างต่อพื้นที่ — สูง = เก็บถี่ = พิกเซลเยอะ = ละเอียด
  • Sampling กำหนด Spatial Resolution (ความละเอียดเชิงพื้นที่ / จำนวนพิกเซล) — ไม่ใช่จำนวนสี!
  • Sampling สูง → รายละเอียดชัด แต่ไฟล์ใหญ่ · Sampling ต่ำ → ภาพเป็นบล็อก (pixelated) เห็นตารางชัด
  • โจทย์ถาม "spatial resolution" / "จำนวนพิกเซล" → ตอบ Sampling

3 · Quantization — ระดับความเข้ม

  • ค่าความเข้มต่อเนื่อง → ปัดเป็นระดับจำกัด (grey levels) — กำหนดโดยบิตต่อพิกเซล
  • ระดับเทา = 2^บิต — 8 บิต = 256 ระดับ · 16 บิต = 65,536 ระดับ · ยิ่งเยอะยิ่งไล่สีเรียบเนียน
  • Quantization Level = จำนวน grey levels — โจทย์ถาม "grey levels" / "ระดับเทา" → ตอบ Quantization
  • False Contours = รอยหยัก/เส้นขั้นบันได ในบริเวณที่ควรไล่สีเรียบ (เช่น ท้องฟ้า) — เกิดจาก Quantization ด้วยระดับเทาน้อยเกินไป · แก้โดยเพิ่มจำนวน grey levels (บิตต่อพิกเซล)

4 · สูตรลด 256 → 16 ระดับ: q = (img // 16) × 16 + 7

  • ที่มา: 0–255 มี 256 ค่า ÷ 16 ช่วง = ช่วงละ 16 ค่า → แต่ละช่วงแทนด้วยค่ากลางของช่วง
  • 1) img // 16 = หาร 16 ปัดเศษทิ้ง → หาว่าอยู่ช่วงไหน (เช่น 210 ÷ 16 = 13.125 → 13)
  • 2) × 16 = กลับมาเป็นจุดเริ่มต้นของช่วง (13 × 16 = 208)
  • 3) + 7 = ขยับไปกลางช่วง (208 + 7 = 215) — เลข 7 = ครึ่งช่วง (16 ÷ 2 − 1)
  • ตัวอย่างที่ต้องคำนวณได้: 210 → 215 · 219 → 215 · 223 → 215 (ทั้ง 3 อยู่ในช่วง 208–223) · 108 → 6×16+7 = 103 · 105, 99 → 103
  • 16 ระดับ = 4 บิต (2⁴ = 16) — เก็บ 4 บิตแทน 8 บิต → ไฟล์เล็กลงครึ่งหนึ่ง
  • ค่าที่อยู่ในช่วงเดียวกัน → ผลลัพธ์เดียวกันเสมอ

5 · Bit-Plane — แยกภาพเป็นชั้นบิต

  • พิกเซล 8 บิต = 8 ชั้น (plane) — ชั้นที่ i เก็บบิตตำแหน่ง i ของทุกพิกเซล (bit 7 6 5 4 3 2 1 0)
  • แต่ละชั้นเป็นภาพ Binary (0/1) — รวม 8 ชั้นกลับคืนเป็นภาพต้นฉบับได้
  • น้ำหนักบิต: bit 7 = 128 · 6 = 64 · 5 = 32 · 4 = 16 · 3 = 8 · 2 = 4 · 1 = 2 · 0 = 1 — ยิ่งซ้ายยิ่งสำคัญ
  • Bit-Plane Slicing: bit_plane[i] = (ex >> i) & 1 — >> i เลื่อนบิตที่ i มาล่างสุด, & 1 ตัดเหลือเฉพาะบิตนั้น (0/1) · วน i = 0–7 ได้ครบ 8 บิต
  • ตัวอย่าง: 147 = 10010011₂ · bit 4 → 147 >> 4 = 9 (1001) → 9 & 1 = 1 ✓
  • MSB = Most Significant Bit = bit 7 (น้ำหนัก 128) — เก็บโครงสร้างหลักของภาพ (bit-plane 7 เห็นโครงร่างชัดเหมือนต้นฉบับ) · ปิดบิต 7: 150 → 22 (มืดทันที)
  • LSB = Least Significant Bit = bit 3–0 (8, 4, 2, 1) — เก็บรายละเอียดเล็ก ๆ + noise (มองดูไม่เป็นภาพ) · ปิดบิต 0: 150 → 149 (แทบไม่ต่าง)

6 · Applications — Compression & Watermark

  • Image Compression (บีบอัด 50%): MSB เก็บโครงสร้าง, LSB เก็บรายละเอียดเล็ก/noise → เก็บบิต 4–7 ทิ้งบิต 0–3 = เหลือข้อมูล 4/8 = 50% — ภาพยังเห็นโครงสร้างชัด แต่ไฟล์เล็กลงครึ่งหนึ่ง (trade-off คุณภาพ vs ขนาด)
  • Watermarking / Steganography: ซ่อนข้อมูลลับ/ลายน้ำใน LSB (bit 0) — เช่น 151 (LSB=1) → 150 (LSB=0) ค่าเปลี่ยนแค่ 1/255 ตาแยกไม่ออก · อ่านกลับ = เอา LSB ของทุกพิกเซลมารวมกัน
  • Watermark = ฝังลายน้ำ/ชื่อเจ้าของพิสูจน์ความเป็นเจ้าของ · Steganography = ซ่อนข้อความลับในภาพ (คนดูเห็นภาพปกติ)

7 · Downsampling & Image Pyramid

  • Downsampling = ลด resolution ของภาพ เช่น 1024×1024 → 512×512 → 256×256
  • ลดครึ่งทั้ง 2 ด้าน = พิกเซลเหลือ ¼ (½ × ½) ไม่ใช่ ½! — 1024→512 ไฟล์/การคำนวณลด 75% (ข้อนี้พลาดประจำ)
  • ทำไมต้อง downsample: เร็วขึ้น (อัลกอริทึมคิดต่อพิกเซล) · ลด bandwidth (ส่งเน็ต/สตรีม) · ลด noise (เฉลี่ยพิกเซล) · Image Pyramid · หลาย scale (SIFT/SURF/ORB/Optical Flow) · ก่อนป้อน ML Model (input ขนาดคงที่) · ประหยัดพื้นที่เก็บ · ดูภาพย่อ (thumbnail)
  • Image Pyramid = ชุดภาพ downsample ต่อเนื่องกันซ้อนเป็นชั้น (1024² → 512² → 256² → 128²) — ใหญ่สุดอยู่ล่าง · ใช้ตรวจจับวัตถุหลายขนาด (Object Detection / Face Detection / SIFT / SURF / ORB)

8 · สูตร & เลขต้องจำก่อนเข้าห้องสอบ

  • Sampling → spatial resolution (ตำแหน่ง/พิกเซล) · Quantization → grey levels (ระดับเทา)
  • ระดับเทา = 2^บิต · 8 บิต = 256 · 16 บิต = 65,536
  • q = (img // 16) × 16 + 7 · 210 → 215 · 108 → 103 · ค่าในช่วงเดียวกันได้ค่าเดียวกัน
  • bit_plane[i] = (ex >> i) & 1 · 147 = 10010011₂
  • MSB = bit 7 = 128 = โครงสร้างหลัก · LSB = bit 0 = 1 = รายละเอียดเล็ก + noise
  • บีบอัด 50% = เก็บบิต 4–7 ทิ้งบิต 0–3 · ซ่อนข้อมูล = LSB
  • Downsample ½×½ = ¼ พิกเซล (ลด 75%) · Pyramid = ภาพหลาย scale ซ้อนกัน

9 · กับดักที่ข้อสอบชอบหลอก

  • ⚠ Sampling ↔ ตำแหน่ง · Quantization ↔ ความเข้ม — อย่าสลับกัน
  • ⚠ False Contours = Quantization ไม่พอ (ระดับเทาน้อยไป) — ไม่ใช่ Sampling
  • ⚠ Downsample 1024→512 = เหลือ ¼ พิกเซล (½×½) — ไม่ใช่ ½
  • ⚠ MSB = bit 7 (128) · LSB = bit 0 (1) — อย่าจำสลับ
  • ⚠ ซ่อนข้อมูล/Steganography ใช้ LSB — ไม่ใช่ MSB
  • ⚠ สูตร q: หารปัดลง → คูณกลับ → +7 — ค่าช่วงเดียวกันได้ผลลัพธ์เดียวกัน (อย่าคิดว่า 219 ≠ 210 แล้วได้ค่าต่าง)
  • ⚠ i = 0 ใน (ex >> i) & 1 คือบิตขวาสุด (LSB) — แถวแรกของตารางคือ bit 7 (MSB)
  • ⚠ 16 ระดับ = 4 บิต (2⁴) — ไฟล์ครึ่งหนึ่งของ 8 บิต
  • ⚠ spatial resolution ≠ จำนวนสี — อย่าเอา Sampling ไปตอบเรื่องสี/ระดับเทา
