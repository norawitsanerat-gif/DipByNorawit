FUNDAMENTAL CONCEPTS

ภาพดิจิทัล คืออะไร?

นิยามจากตำรา: ภาพ คือฟังก์ชัน 2 มิติ f(x, y) — ฟังดูยาก แต่จริง ๆ แค่ 2 อย่าง

อ่านสูตร f(x, y) แบบจับมือ
f(x, y)

อ่านว่า: "ภาพ = ค่าความเข้ม ณ ตำแหน่ง (x, y)"

📍 x, y = ตำแหน่งพิกัด (x = แนวนอน, y = แนวตั้ง) บอกว่าจุดนี้อยู่ตรงไหนของภาพ
🎨 ค่าของ f = ความเข้มตรงตำแหน่งนั้นมีความสว่าง/ระดับเทา (intensity / gray level) เท่าไร

แต่ละช่อง = 1 ตำแหน่ง (x, y) ที่มีค่าความเข้มของตัวเอง — นี่คือภาพดิจิทัล

เมื่อไหร่ถึงเรียกว่า "ดิจิทัล"

เมื่อทั้ง x, y (ตำแหน่ง) และ ค่าความเข้ม ถูกแบ่งเป็นค่าจำกัด (discrete / finite) — ไม่ต่อเนื่องเป็นเส้นเรียบอีกต่อไป → เรียกว่า ภาพดิจิทัล

ประกอบด้วยอะไร?

องค์ประกอบจำนวนจำกัด (finite number of elements) — แต่ละตัวมี ตำแหน่ง (location) และ ค่า (value) ของตัวเอง เรียกว่า พิกเซล (pixel)

จำแบบนี้ภาพ = f(x, y) · x, y = ตำแหน่ง · f = ความเข้ม · ค่าไม่ต่อเนื่อง = ดิจิทัล

FUNDAMENTAL CONCEPTS

พิกเซล (Pixel)

Pixel = Picture Element — จุดเล็กที่สุดของภาพดิจิทัล เหมือนตารางสี่เหลี่ยมเล็ก ๆ เรียงต่อกัน

1 พิกเซล เก็บอะไร?

1. ตำแหน่ง (x, y) ว่าอยู่แถวไหน คอลัมน์ไหน
2. ค่า (value) — ระดับเทา (grayscale) หรือสี (RGB/BGR)

ยิ่งพิกเซลเยอะ = ยิ่งละเอียด

ภาพ 1920×1080 = 2,073,600 พิกเซล — แต่ละจุดมีค่าของตัวเอง เรียงกันเป็นภาพที่เราเห็น

คำที่พบบ่อยpels = picture elements · ตัวที่ใช้บ่อยที่สุด = pixel — ใน OpenCV เข้าถึงด้วย img[y, x]
ซูมเข้าไปดู — เห็นเป็นตารางพิกเซล

6 ช่องนี้คือ 6 พิกเซล — แต่ละช่องมีระดับเทาของตัวเอง

COLOR DEPTH

Color Depth — บิตต่อพิกเซล

Color Depth (Bit Depth) = จำนวนบิตที่ใช้เก็บ 1 พิกเซล — ยิ่งบิตมาก ยิ่งมีสี/ระดับเทาเยอะ

กฎเหล็ก: จำนวนค่าที่เป็นไปได้ = 2^บิต
11 bit → 2^1 = 2 ค่า (0 หรือ 1 — ขาว/ดำ)
22 bit → 2^2 = 4 ค่า
38 bit → 2^8 = 256 ค่า (0–255 ระดับเทา)
424 bit → 2^24 = 16.7 ล้าน สี (True Color)
ทำไมต้องรู้?บิตต่อพิกเซลเป็นตัวตั้งต้นของขนาดไฟล์ — 1 พิกเซล 8 บิต = 1 ไบต์, 24 บิต = 3 ไบต์
1-bit · ขาวดำ
8-bit · เทา 256
24-bit · RGB
32-bit · RGBA

เหตุผลที่ 8 บิต = 256

8 บิต = เลขฐานสอง 8 หลัก: 00000000 ถึง 11111111 = 0 ถึง 255 = 256 ค่า — พอดีกับ uint8 ใน OpenCV

COLOR DEPTH · 16-BIT

16-bit High Color (RGB565)

แบ่ง 16 บิตเป็น: แดง 5 · เขียว 6 · น้ำเงิน 5 — ทำไมเขียวถึงได้เยอะที่สุด?

จัดสรรบิตแบบ RGB565
R · 5 บิต
G · 6 บิต
B · 5 บิต
RRRRR GGGGGG BBBBB = 16 บิต
1แดง 5 บิต → 2^5 = 32 ระดับ
2เขียว 6 บิต → 2^6 = 64 ระดับ
3น้ำเงิน 5 บิต → 2^5 = 32 ระดับ
4รวม = 32 × 64 × 32 = 65,536 สี

ทำไมเขียว 6 บิต?

เซลล์รับแสง (cones) ในตาคน ไวต่อสีเขียวมากที่สุด — ให้บิตเขียวเยอะ = ภาพดูดีขึ้นด้วยบิตเท่าเดิม

เคยใช้ที่ไหน?

จอมือถือ/จอคอมรุ่นเก่า ใช้ High Color เพราะไฟล์เล็กกว่า 24-bit — ประหยัดหน่วยความจำหน้าจอ

เทคนิคสอบเจอคำว่า 565 → นึกถึง High Color 16-bit · จำนวนสี = 65,536

COLOR DEPTH · 24-BIT

24-bit True Color (RGB)

R / G / B อย่างละ 8 บิต = 2^8 × 2^8 × 2^8 = 16,777,216 สี ≈ 16.7 ล้าน

คำนวณ 2^24 ด้วยเครื่องคิดเลขธรรมดา
1แต่ละช่อง 8 บิต → 2^8 = 256 ค่า
23 ช่อง: 256 × 256 × 256
3กด: 256 × 256 = 65,536 แล้ว × 256 = 16,777,216
4นั่นคือ "True Color" — ภาพสีเต็มรูปแบบมาตรฐาน

ตัวอย่างสีจริง

R=255
G=255
B=255
RGB ทั้งหมด

ผสมกันได้ 16.7 ล้านสี — มากพอที่ตาคนจะแยกไม่ออกว่าสีไหนใกล้กัน

จำแบบนี้24-bit = True Color = 16.7 ล้านสี = R8+G8+B8 — ภาพ 1 พิกเซลใช้ 3 ไบต์

COLOR DEPTH · 32-BIT

32-bit RGBA (Alpha Channel)

RGBA = RGB 24 บิต + Alpha 8 บิต — ช่องความโปร่งใส (transparency)

Alpha = ระดับความโปร่งใส
0Alpha = 0 → โปร่งใสสนิท (มองทะลุ)
128Alpha = 128 → โปร่งใสครึ่งหนึ่ง
255Alpha = 255 → ทึบแสง (ปกติ)
ใช้ที่ไหน?ไฟล์ PNG โปร่งใส, การซ้อนภาพ (overlay), UI/UX, งานตัดต่อ

ซ้อนภาพด้วย Alpha

ภาพบนมี Alpha → เห็นภาพล่างลอดผ่าน — หลักการเดียวกับ watermark หรือพื้นหลังโปร่งใสของ sticker

32 บิต = 4 ไบต์/พิกเซล

R(1) + G(1) + B(1) + A(1) = 4 ไบต์ — ใหญ่กว่า 24-bit แต่ได้ความโปร่งใส

เทคนิคสอบA = Alpha = ความโปร่งใส · 0 โปร่งใส · 255 ทึบ

IMAGE TYPES · 1/4

Binary Image — ภาพขาวดำล้วน

1 บิตต่อพิกเซล — ค่าเป็น 0 (ดำ) หรือ 1 (ขาว) เท่านั้น ไม่มีเทาอยู่กลาง

ตัวอย่าง: ตัวอักษร A ขนาด 5×7

แต่ละช่องเก็บ 0 หรือ 1 เท่านั้น — 1 บิต/พิกเซล

ใช้กับงานอะไร?

ผลลัพธ์ของ Threshold / Segmentation — แยก object (ขาว) ออกจาก background (ดำ) ก่อนวิเคราะห์ต่อ

เทคนิคสอบBinary = 0/1 = 2 ค่า = 1 บิต — อย่าสับสนกับ Grayscale (0–255)

IMAGE TYPES · 2/4

Grayscale Image — ภาพระดับเทา

เก็บเฉพาะ ความเข้ม (intensity) — 8 บิต = ระดับเทา 0 (ดำ) ถึง 255 (ขาว)

แถบเทา 0 → 255
0 = ดำ127 ≈ เทา 50%255 = ขาว
ใน OpenCVอ่านภาพ grayscale ด้วย cv2.imread(img, 0) หรือ cv2.cvtColor(img, cv2.COLOR_BGR2GRAY) — เหลือ 1 ช่อง

ทำไมหลายงานต้องใช้ grayscale ก่อน?

หลายอัลกอริทึม (threshold, histogram, edge) ทำงานกับ 1 ช่อง — ง่ายและเร็วกว่า 3 ช่องสี

ค่า 0–255 = 256 ระดับ

8 บิต = 1 ไบต์/พิกเซล — ไฟล์เล็กกว่า RGB 3 เท่า เหมาะเป็นขั้นแรกของ pipeline

เทคนิคสอบGrayscale 8-bit → 256 ระดับเทา (0–255) — 1 พิกเซล = 1 ไบต์

COLOR MODELS

Color Model คืออะไร?

Color Model (Color Space) = วิธี/ระบบที่ใช้แทนสีเป็นตัวเลข — แต่ละระบบเหมาะกับงานต่างกัน

สีเดียวกัน แต่เขียนได้หลายระบบ

สีส้มนี้แทนได้ด้วย…

RGBR=255, G=165, B=0
HSLhsl(39, 100%, 50%)
HSVhsv(39, 100%, 100%)
CMYKC=0, M=35%, Y=100%, K=0%

ทำไมต้องมีหลายระบบ?

จอใช้ RGB (รวมแสง) · เครื่องพิมพ์ใช้ CMYK (ลบแสง) · นักออกแบบชอบ HSL/HSV (เข้าใจง่าย) · งานวิดีโอใช้ YCrCb

ระบบหลัก ๆ

RGB · CMYK · HSL · HSV · LAB · YCrCb — สไลด์ถัดไปจะไล่ทีละตัว

จำแบบนี้Color Model = ระบบพิกัดของสี · สีเดียวกันแปลงไปมาระหว่างระบบได้ (cvtColor)

COLOR MODELS · RGB

RGB Model — แดง เขียว น้ำเงิน

Additive (รวมแสง) — ใช้กับจอภาพ · สีขาว = รวม R+G+B ครบ · สีดำ = ไม่มีแสง

ผสมแสง 3 สีปฐมภูมิ

แดง+เขียว = เหลือง · แดง+น้ำเงิน = ม่วง · เขียว+น้ำเงิน = ฟ้า · รวมหมด = ขาว

Additive Color

จอปล่อยแสง R/G/B ออกมา — ยิ่งรวมแสงมากยิ่งสว่าง → ขาว = R255 G255 B255

OpenCV = BGR (ระวัง!)

OpenCV อ่านภาพสีมาเรียง BGR ไม่ใช่ RGB — ถ้าแสดงด้วย Matplotlib โดยไม่แปลง จะเห็นสีแดงกับน้ำเงินสลับกัน

เทคนิคสอบRGB = จอ (additive) · BGR = ลำดับใน OpenCV · cvtColor(COLOR_BGR2RGB) ใช้แปลง

RGB vs CMYK

RGB รวมแสง (จอ) เริ่มดำ → ขาว
CMYK ลบแสง (พิมพ์) เริ่มขาว → ดำ

เทคนิคสอบCMYK = งานพิมพ์ · K = Black · subtractive = ลบแสง

COLOR MODELS · HSL / HSV

HSL / HSV — สีแบบคนเข้าใจ

แทนสีด้วย Hue (สี) + Saturation (ความสด) + Lightness/Value (ความสว่าง)

Hue = วงล้อสี 0–360°
0° แดง120° เขียว240° น้ำเงิน360° = 0°
HHue — เฉดสี เป็นองศา 0–360°
SSaturation — ความสดของสี 0–100% (0 = เทา)
L / VLightness/Value — ความสว่าง 0–100%

HSL vs HSV ต่างกันตรงไหน?

HSL: L=100% → ขาวเสมอ (สีจางลงเมื่อสว่าง)
HSV: V=100% → สีเต็มสด (ไม่จาง) — HSV ใช้เยอะในงานคอมพิวเตอร์กราฟิก

นิยมในงาน UI/UX

CSS มี hsl()/hsv() ใช้โดยตรง — เปลี่ยนความสว่าง/ความสดได้ง่ายกว่า RGB

เทคนิคสอบHue = องศา 0–360 · Saturation = % · Lightness/Value = % · 0° = แดง

COLOR MODELS · OTHERS

LAB / YCrCb — Color Space อื่น ๆ

สองระบบนี้แยก "ความสว่าง" ออกจาก "สี" — ใช้เยอะในงานวิเคราะห์สีและวิดีโอ

LAB

L = Lightness (ความสว่าง) · a = เขียว→แดง · b = น้ำเงิน→เหลือง

Lความสว่างแยกออกจากสี
aแกนเขียว (−) ถึงแดง (+)
bแกนน้ำเงิน (−) ถึงเหลือง (+)

นิยมในงานวิเคราะห์/เทียบสี เพราะใกล้เคียงการมองเห็นของคน

YCrCb

Y = Luminance (ความสว่าง) · Cr = แดงต่าง · Cb = น้ำเงินต่าง

Yความสว่าง (ขาว-ดำ)
Crสีแดง − luminance
Cbสีน้ำเงิน − luminance

ใช้กับวิดีโอ/ทีวี (JPEG, MPEG) — ตากันไวต่อความสว่าง เลยให้ Y เยอะกว่า

จุดร่วมLAB และ YCrCb แยกความสว่าง (L/Y) ออกจากสี — เทคนิค equalize histogram ภาพสี มักทำที่ช่อง L/Y เท่านั้น
