PREVIEW

ทำไมต้องใช้ สี ในการประมวลผลภาพ?

คำตอบสั้น ๆ: เพราะสีเป็นตัวอธิบายที่ทรงพลังที่สุดอย่างหนึ่งของภาพ

สี = Powerful Descriptor

สีช่วย ระบุและแยกวัตถุ (object identification & extraction) — เช่น การหาใบหน้าด้วยสีผิว (face detection using skin colors) เร็วและง่ายกว่าการวิเคราะห์รูปร่างอย่างเดียว

ตาคนเก่งเรื่องสี

มนุษย์สามารถแยก เฉดสีและความเข้มได้หลายพันเฉด (thousands of color shades & intensities) — เทียบกับโทนเทา (gray) ที่แยกได้แค่ สองโหลกว่า (two dozen shades)

จำแบบนี้สีแยกวัตถุได้ดีกว่า · คนแยกสีได้หลายพันเฉด แต่แยกเทาได้แค่ 2 โหลกว่า
ลองสังเกต: ภาพเดียวกัน ต่างกันแค่สี
แอปเปิลแดง แอปเปิลเขียว แยกได้ในเสี้ยววินาที
แต่ถ้าเป็นภาพเทา แอปเปิลทั้งสองแทบแยกไม่ออก

PREVIEW

การประมวลผลภาพสี แบ่งเป็น 2 ประเภท

จำแค่นี้ก่อน: Full-color = ภาพสีจริง · Pseudo-color = ใส่สีให้ภาพเทา

Full-color Processing

ภาพถูกถ่าย/รับเข้ามาจาก เซนเซอร์หรืออุปกรณ์สีเต็มรูปแบบ (full-color sensor / equipment) โดยตรง — สีเป็นข้อมูลจริงจากกล้อง

ตัวอย่าง: ภาพจากกล้องมือถือ/กล้องดิจิทัลสมัยนี้ — แต่ละพิกเซลมีค่าสี R, G, B จริง

Pseudo-color Processing

ในอดีต ยังไม่มี color sensor / ฮาร์ดแวร์สี จึงต้อง กำหนดสีให้กับช่วงความเข้มของภาพเทา (monochrome intensities) — สีที่เห็นเป็นสีที่เรา "ใส่" ลงไป ไม่ใช่สีจริง

ตัวอย่าง: ภาพเอกซเรย์ / ภาพความร้อน ที่ย้อมสีตามช่วงความเข้มเพื่อให้ตาอ่านง่ายขึ้น
Exam Tipข้อสอบถามว่า "ข้อใดคือ Pseudo-color?" → คำตอบคือ กำหนดสีให้กับช่วงความเข้มของภาพ monochrome — อย่าสับสนกับภาพจากกล้องสีจริง

COLOR FUNDAMENTALS

พื้นฐานของสี: 2 มุมมอง

เรื่องสีต้องมอง 2 ด้านประกอบกัน — ด้านฟิสิกส์ กับด้านสมองของคน

Physical Phenomenon

ธรรมชาติทางฟิสิกส์ของสีเป็นสิ่งที่ รู้จักและวัดได้ — แสงคือคลื่นแม่เหล็กไฟฟ้า ความยาวคลื่นต่างกัน = สีต่างกัน (เราจะเรียนเรื่องนี้ต่อในสไลด์ Visible Light)

Physio-psychological Phenomenon

สมองมนุษย์ รับรู้และตีความสี อย่างไร — ทำไมสีเดียวกัน ฉากเดียวกัน คนดูอาจเห็นต่างกันได้ นี่คืออีกครึ่งของเรื่องสี

📜 1666 · Isaac Newton — ทดลองหักเหแสงขาวด้วยปริซึม พบว่าแสงขาวประกอบด้วยสีรุ้ง 7 สี นี่คือจุดเริ่มต้นของศาสตร์เรื่องสี
💡 สรุป — สี = ฟิสิกส์ (แสงที่วัดได้) + จิตวิทยา/สรีรวิทยา (ตากับสมองตีความ) — เรียนทั้งสองด้านถึงจะเข้าใจภาพสี

แสงสี (chromatic light) ครอบคลุม EM spectrum ช่วง 400–700 นาโนเมตร (nm)

แถบ EM spectrum — ช่องที่ตาเรามองเห็น (มีสี)

สีที่ตามองเห็นบนวัตถุ = ?

แสงที่สะท้อนจากวัตถุนั้น (the light reflected from the object) — แหล่งกำเนิดแสง (illumination source) ส่องฉาก แล้วตารับแสงสะท้อนกลับมา ไม่ใช่แสงที่วัตถุดูดซับ

วงจรการมองเห็นสี

Illumination source → ส่อง scene → วัตถุ สะท้อน แสงบางช่วงคลื่น → ตา (eye) รับ reflection → สมองแปลเป็น "สี"

Exam Tipจำ 2 อย่าง: 400–700 nm (ช่วงแสงที่มองเห็น) และ สีที่เห็น = แสงสะท้อนจากวัตถุ

COLOR FUNDAMENTALS

ปริมาณทางฟิสิกส์ 3 อย่าง ของแหล่งแสง

คนละตัว หน่วยคนละอย่าง — นี่คือจุดที่ข้อสอบชอบจับผิด

Radiance พลังงานทั้งหมดที่ไหลจากแหล่งแสง (total energy)
หน่วย: วัตต์ (W)
Luminance พลังงานที่ผู้สังเกตรับรู้จากแหล่งแสง (perceived)
หน่วย: ลูเมน (lm)
Brightness ตัวอธิบายแบบsubjective วัดยาก
คล้าย intensity แบบ achromatic
ตัวอย่างที่ต้องจำแสงอินฟราเรดไกล (far infrared) มี radiance สูง แต่ luminance = 0 — เพราะมีพลังงานจริง (W เยอะ) แต่ตามนุษย์มองไม่เห็น จึงรับรู้ได้ 0 (lm = 0)

ตาเรามี Cones ประมาณ 6–7 ล้านเซลล์ — 3 กลุ่มรับแสง: แดง 65% · เขียว 33% · น้ำเงิน 2%

ทำไมสัดส่วนไม่เท่ากัน?

เพราะธรรมชาติเลือกให้ตามนุษย์ไวต่อแสงแดง-เขียวมากที่สุด (จำเป็นต่อการมองในป่า/แยกผลไม้) — นี่คือที่มาของระบบสีแบบ 3 สี (trichromatic)

อีกประเภท: Rods

นอกจาก Cones ยังมี Rods (~120 ล้านเซลล์) ที่รับแสงน้อย/ขาวดำ — ทำงานตอนที่แสงสลัว

Exam Tipจำตัวเลขเป๊ะ: Cones 6–7 ล้าน · แดง 65% · เขียว 33% · น้ำเงิน 2%

COLOR FUNDAMENTALS

สีปฐมภูมิ & ทุติยภูมิ ของแสง

ในปี 1931 CIE (International Commission on Illumination) กำหนดความยาวคลื่นเฉพาะให้สีปฐมภูมิ

CIE 1931 — ความยาวคลื่นปฐมภูมิ

• Blue (B) = 435.8 nm
• Green (G) = 546.1 nm
• Red (R) = 700 nm
หมายเหตุ: ไม่มีสีเดียวใดที่เรียกว่า "แดง/เขียว/น้ำเงินแท้ 100%" ได้จริง (no single color may be called red, green, or blue)

สีทุติยภูมิ (Secondary) — บวกกันแบบ additive

• G + B = Cyan (ฟ้าเขียว)
• R + G = Yellow (เหลือง)
• R + B = Magenta (ม่วงแดง)

Exam Tipจำชุดตัวเลข CIE 1931: B=435.8 · G=546.1 · R=700 nm และสูตรทุติยภูมิ: G+B=Cyan · R+G=Yellow · R+B=Magenta

COLOR FUNDAMENTALS

สีของแสง vs สีของเม็ดสี

แสงใช้การบวก (additive) แต่เม็ดสีใช้การลบ (subtractive) — สีปฐมภูมิคนละชุดกัน!

เม็ดสีปฐมภูมิ = สีที่ "ดูดซับ" สีปฐมภูมิของแสง 1 สี และสะท้อน/ส่งผ่านอีก 2 สี

Cyan
ดูดซับ R (แดง)
Magenta
ดูดซับ G (เขียว)
Yellow
ดูดซับ B (น้ำเงิน)
สีของแสง (additive)ปฐมภูมิ = R, G, B — ยิ่งบวกกันยิ่งสว่าง (R+G+B = ขาว) ใช้กับจอ/ทีวี
สีของเม็ดสี (subtractive)ปฐมภูมิ = Cyan, Magenta, Yellow — ยิ่งผสมกันยิ่งมืด (C+M+Y ≈ ดำ) ใช้กับงานพิมพ์
Exam Tipเม็ดสีปฐมภูมิ = Cyan, Magenta, Yellow — Cyan ดูด R · Magenta ดูด G · Yellow ดูด B

COLOR FUNDAMENTALS

CIE XYZ Model

แปลง RGB เป็นระบบพิกัดสีที่มาตรฐาน — ฟังดูยาก แต่หัวใจคือสมการเดียว

แปลง RGB → XYZ (เมทริกซ์)

X = 0.431R + 0.342G + 0.178B
Y = 0.222R + 0.707G + 0.071B
Z = 0.020R + 0.130G + 0.939B

Normalized Tristimulus — สมการสำคัญ

x = X/(X+Y+Z) · y = Y/(X+Y+Z) · z = Z/(X+Y+Z)
→ x + y + z = 1 เสมอ!

เพราะ x+y+z=1 ดังนั้นแค่ x, y (chromaticity coordinates) ก็พอจะอธิบายสีทั้งหมดได้ — z หาได้จาก 1 - x - y
จำแบบนี้x + y + z = 1 → ใช้แค่ x, y ก็อธิบายสีได้ครบ (ข้อสอบถามบ่อยมาก)

COLOR MODELS

RGB Model & Pixel Depth

RGB = ลูกบาศก์สี 3 แกน · Pixel depth = จำนวนบิตแทนแต่ละพิกเซล

RGB color cube — มุมของลูกบาศก์ = สีหลัก 8 สี

ขาว = R+G+B ทั้งหมด · ดำ = ไม่มีสีใดเลย

Pixel Depth คืออะไร?

คือ จำนวนบิตที่ใช้แทนแต่ละพิกเซลใน RGB space — ยิ่งบิตเยอะ ยิ่งแสดงสีละเอียด

Full-color = 24-bit RGB

(R, G, B) = (8, 8, 8) บิต → 8+8+8 = 24 บิตต่อพิกเซล = 16.7 ล้านสี

Exam Tip24-bit RGB = 3 ช่อง × 8 บิต = 24 บิต/พิกเซล — ข้อสอบอาจถาม "แต่ละช่องใช้กี่บิต?" → ตอบ 8

COLOR MODELS

Safe RGB Colors — 216 สี

บางแอปพลิเคชันใช้แค่สี "ปลอดภัย" ชุดหนึ่งก็พอ — สีที่เว็บ/เบราว์เซอร์แสดงได้แน่นอน

Safe color cube — 6 × 6 × 6 = 216 สี

แต่ละช่อง (R, G, B) ใช้แค่ 6 ค่า → 6³ = 216

ทำไมต้อง "Safe"?

ในยุคจอ 256 สี / เว็บแรก ๆ เบราว์เซอร์แต่ละตัวแสดงสีไม่เหมือนกัน — สีชุดนี้รับประกันว่า แสดงเหมือนกันทุกเครื่อง (safe Web / browser colors)

คำนวณแบบจับมือ

1. แต่ละช่อง (R, G, B) ใช้ 6 ค่า
2. 3 ช่อง → 6 × 6 × 6
3. = 216 สี ✓

Exam Tip(6)³ = 216 · ข้อสอบถาม "ค่าต่อช่อง" → ตอบ 6 · ถาม "ทั้งหมด" → ตอบ 216

COLOR MODELS

CMY Model (+Black = CMYK)

CMY = สีทุติยภูมิของแสง = สีปฐมภูมิของเม็ดสี — ใช้สร้าง hardcopy output (งานพิมพ์)

สูตรแปลง RGB → CMY

C = 1 - R
M = 1 - G
Y = 1 - B

ค่า R, G, B ใช้แบบ normalized (0–1) — CMY คือ complement (ส่วนเติมเต็ม) ของ RGB นั่นเอง

ตัวอย่าง: R = 1 (แดงเต็ม)

C = 1 - 1 = 0
M = 1 - 0 = 1
Y = 1 - 0 = 1
→ แดงเต็ม = Cyan 0, Magenta 1, Yellow 1 (ถูกต้อง: M+Y = แดง)

ทำไมต้อง + K (Black)?

CMY ผสมกันได้ดำ ไม่สมบูรณ์ (ออกน้ำตาล/เทา) จึงเพิ่มหมึกดำ K แยกต่างหาก → CMYK (K = Key/Black)

Exam Tipสูตร C = 1 - R, M = 1 - G, Y = 1 - B + K ย่อมาจาก Black ใช้กับงานพิมพ์

COLOR MODELS

HSI Model — ตรงกับวิธีที่คนบรรยายสี

ลองถามตัวเอง: จะบรรยายสี "แอปเปิลเขียวลูกนี้" ยังไง? ไม่มีใครตอบว่า R=120, G=180, B=60 หรอก — แต่ตอบว่า เขียว, สดใส, สว่างพอควร

Hue + Saturation อยู่บนสามเหลี่ยมสี
สีเดียวกัน (hue) อยู่บนเส้นเดียวกัน

Intensity (ความสว่าง) เป็นแกนตั้งฉากออกจากระนาบ

Hue (ฮิว)

คุณลักษณะของสี (color attribute) — บอกว่าเป็นสีอะไร: แดง เขียว น้ำเงิน...

Saturation (ความอิ่ม)

ความบริสุทธิ์ของสี — ขาว = 0 (ไม่มีสี) · สีปฐมภูมิเต็ม = 1 (บริสุทธิ์สุด)

Intensity / Brightness

ความสว่าง — แนวคิดแบบ achromatic (ไม่มีสี) เหมือนระดับเทา

Exam TipSaturation: ขาว = 0 · สีปฐมภูมิ = 1 — ข้อสอบถามค่านี้บ่อย

กำหนดสีให้ค่าความเข้มเทา ตามเกณฑ์ที่ตั้งไว้ — เพื่อช่วยมนุษย์มองเห็นและตีความภาพเทา

ภาพเทา (ระดับ 0–255)
แบ่งเป็น 6 ชิ้น (slices) แล้วย้อมสีแต่ละชิ้น

มองแบบ 3 มิติ

ภาพเทา = ระนาบที่ความสูงแต่ละจุดคือระดับเทา — เอาระนาบ (plane) ตัดแบ่งเป็นชั้น แล้วให้แต่ละชั้นคนละสี

ยิ่ง slicing เยอะ = ยิ่งสีเยอะ

More slicing planes → more colors — เห็นรายละเอียดระดับเทาแยกเป็นสีต่าง ๆ ชัดเจนขึ้น

ตัวอย่างการใช้งานจริง

ภาพทดสอบรังสี (radiation test pattern) · ภาพ X-ray รอยเชื่อมโลหะ (weld) · สถิติฝน (rainfall) — ใช้สีแยกช่วงค่าต่าง ๆ ให้อ่านง่าย

Exam TipIntensity slicing = แบ่งระดับเทาเป็นช่วง แล้วกำหนดสีให้แต่ละช่วง

PSEUDO-COLOR

Gray-level → Color Transformation

อีกวิธีของ pseudo-color: ใช้ฟังก์ชันแปลงค่าระดับเทาเป็นค่าสี

Intensity slicing = piecewise linear transformation
085170255

แต่ละช่วงของระดับเทา (0–255) ถูกแมปเป็น "บันได" ขึ้นไปยังสีที่กำหนด

สองแนวทาง

• Intensity slicing: piecewise linear — แบ่งช่วงเป็นท่อน ๆ
• General gray→color: ฟังก์ชันอิสระ (R = f₁(L), G = f₂(L), B = f₃(L)) — แต่ละช่องมีฟังก์ชันของตัวเอง

รวมภาพ monochrome หลายภาพ

Application: นำภาพเทาหลายภาพมาเป็นช่อง R, G, B ของภาพสีเดียว — เช่น multi-spectral images (ภาพดาวเทียม Washington D.C.: R, G, B + near-infrared ที่ไวต่อมวลชีวภาพ)

จำแบบนี้Pseudo-color = ใส่สีให้ภาพเทา มี 2 วิธี: slicing (แบ่งช่วง) + gray→color (ฟังก์ชันแปลง)

FULL-COLOR PROCESSING

Full-color Processing — 2 หลักคิด

การประมวลผลภาพสีจริง มีหลักคิด 2 แบบ

แบบที่ 1: ไล่ทีละ component

แยกภาพเป็นช่อง R, G, B (หรือ H, S, I) แล้วประมวลผล ทีละช่องอิสระ (per-component) — ทำกับแต่ละช่องเหมือนภาพเทา แล้วนำกลับมารวม

เช่น เพิ่ม contrast ให้ช่อง R, G, B อย่างละเท่า ๆ กัน

แบบที่ 2: ประมวลผลทั้งภาพ

มองทุกพิกเซลเป็น เวกเตอร์สี (color vector) แล้วประมวลผลทีละพิกเซลทั้งเวกเตอร์ (vector-based) — ไม่แยกช่อง

เช่น หมุนสีทั้งภาพ (color rotation) ด้วยเมทริกซ์
Exam Tipจำ 2 คำ: per-component = ทำทีละช่อง · vector-based = ทำทั้งเวกเตอร์สี

FULL-COLOR PROCESSING

Color Transformations

หลักคิดเดียวกับภาพเทา s = T(r) — แต่ภาพสีต้องแปลงครบทั้ง 3 component

sᵢ = Tᵢ(r₁, r₂, r₃)  สำหรับ i = 1, 2, 3
📥 r₁, r₂, r₃ = ค่าสี 3 ช่องของพิกเซลต้นทาง (เช่น R, G, B)
🔄 Tᵢ = ฟังก์ชันแปลงของช่อง i — อาจใช้ค่าจากทั้ง 3 ช่องมาคิด (ไม่ใช่แค่ช่องตัวเอง)
📤 sᵢ = ผลลัพธ์ช่องที่ i — ทำครบ i = 1, 2, 3 ได้พิกเซลใหม่ทั้ง 3 ช่อง
🧮 จับมือ ภาพเทา: s = T(r) แปลงค่าเดียว · ภาพสี: ต้องแปลง 3 ช่องพร้อมกันด้วย T₁, T₂, T₃
Exam Tipการแปลงภาพสีต้องทำกับ ทุก component (ทั้ง 3 ช่อง) — ไม่ใช่แค่ช่องเดียว

FULL-COLOR PROCESSING

Smoothing & Sharpening ภาพสี

ใช้หลักเดียวกับภาพเทา แต่ต้องระวัง: ทำที่ HSI intensity ไม่ใช่ที่ RGB ตรง ๆ

Smoothing (เบลอ) เฉลี่ยค่าพิกเซลรอบข้าง (neighborhood averaging)
ทำกับทั้ง 3 ช่อง RGB หรือทำที่ intensity ของ HSI อย่างเดียว
Sharpening (คมชัด) ใช้ Laplacian (หาอนุพันธ์อันดับ 2) เพิ่มความคม
ทำทีละ component ก็ได้
⚠ ข้อควรระวัง ถ้าทำที่ RGB ตรง ๆ สีอาจเพี้ยน — วิธีที่ปลอดภัย: แปลงเป็น HSI แล้วทำที่ intensity เท่านั้น (hue/saturation ไม่แตะ)
🛠 วิธีทำ (จับมือ) 1) แปลง RGB → HSI · 2) ทำ smoothing/sharpening เฉพาะช่อง Intensity (เหมือนภาพเทา) · 3) แปลง HSI กลับ → RGB
💡 ทำไม? เพราะ H (hue) กับ S (saturation) คือ "ข้อมูลสี" — ถ้าไปปรับจะสีเพี้ยน แต่ I (intensity) คือ "ความสว่าง" — ปรับแล้วภาพคม/เบลอโดยสีไม่เปลี่ยน
Exam Tipจำไว้ว่า: smoothing/sharpening ภาพสีที่ถูกต้อง = ทำที่ Intensity ของ HSI ไม่ใช่ RGB ตรง ๆ
