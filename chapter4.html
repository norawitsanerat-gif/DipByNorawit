BRIGHTNESS

Brightness — ความสว่าง

บวก/ลบค่าคงที่ (beta) กับทุกพิกเซล — ภาพสว่างขึ้นหรือมืดลงเท่า ๆ กันทั้งภาพ

ผลของ beta ต่อภาพ
beta = −50 (มืด)
เดิม
beta = +50 (สว่าง)
+betaทุกพิกเซลบวก beta → ภาพสว่างขึ้น
−betaทุกพิกเซลลบ beta → ภาพมืดลง

โค้ด

bright = cv2.convertScaleAbs(img, beta=50)
dark   = cv2.convertScaleAbs(img, beta=-50)

จำง่าย ๆ

beta = ตัวบวก/ลบ (offset) — เหมือนเลื่อนความสว่างทั้งภาพขึ้น-ลง

เทคนิคสอบคำถามเรื่อง "ความสว่าง" → beta · บวก = สว่าง · ลบ = มืด

CONTRAST

Contrast — คอนทราสต์

คูณค่าคงที่ (alpha) กับทุกพิกเซล — ยิ่งคูณมาก ยิ่ง "ห่างกัน" ชัดขึ้น

ผลของ alpha ต่อคอนทราสต์
alpha = 0.5 (ซีด)
เดิม
alpha = 1.8 (เข้มข้น)
alpha > 1ระยะห่างของค่ากว้างขึ้น → contrast เพิ่ม
alpha < 1ค่ารวมเข้าหากัน → contrast ลด (ซีด)

โค้ด

contrast = cv2.convertScaleAbs(img, alpha=1.8, beta=0)

จำง่าย ๆ

alpha = ตัวคูณ (scale) — ขยาย/บีบระยะห่างระหว่างค่ามืดกับสว่าง

เทคนิคสอบคำถามเรื่อง "คอนทราสต์" → alpha · >1 เพิ่ม · <1 ลด

COMBINED FORMULA

Brightness × Contrast

สูตรเดียวทำทั้งสองอย่าง: new = (alpha × pixel) + beta

ทำไมต้องคูณก่อนแล้วบวก?
1alpha × pixel — ปรับคอนทราสต์ก่อน (คูณ)
2+ beta — แล้วค่อยปรับความสว่าง (บวก)
3คลิป 0–255 — ค่าเกิน 255 → 255, ต่ำกว่า 0 → 0
new = cv2.convertScaleAbs(img, alpha=1.5, beta=30)
# new = (1.5 × pixel) + 30  ทุกพิกเซล

ลองคำนวณ: pixel = 100

(1.5 × 100) + 30 = 150 + 30 = 180

ลองคำนวณ: pixel = 200

(1.5 × 200) + 30 = 300 + 30 = 330 → คลิปเป็น 255

เทคนิคสอบจำลำดับ: คูณ alpha (contrast) ก่อน → บวก beta (brightness) → คลิป 0–255

OPENCV CODE

cv2.convertScaleAbs() — โค้ดจริง

คำสั่งเดียวจบ: คูณ alpha, บวก beta, คลิป 0–255, แปลงเป็น uint8 — ทั้งหมดในตัว

โค้ดตัวอย่างครบ 
import cv2

img = cv2.imread("image.jpg")

# สว่างขึ้น + คอนทราสต์สูงขึ้น
enhanced = cv2.convertScaleAbs(img, alpha=1.5, beta=30)

# มืดลง
dark = cv2.convertScaleAbs(img, alpha=1.0, beta=-40)

cv2.imwrite("enhanced.jpg", enhanced)
alphaตัวคูณ (contrast)
betaตัวบวก (brightness)
Absค่าสัมบูรณ์ + แปลงเป็น uint8 อัตโนมัติ

ทำไมชื่อ "ScaleAbs"?

Scale = คูณ alpha + บวก beta · Abs = ใช้ค่าสัมบูรณ์กันค่าลบ · ผลลัพธ์ถูกคลิปที่ 0–255 ให้เอง

เขียนเองก็ได้ (เหมือนกัน)

new = (img.astype(float) * 1.5 + 30)
new = np.clip(new, 0, 255).astype("uint8")
เทคนิคสอบconvertScaleAbs(img, alpha, beta) = (alpha×pixel) + beta คลิป 0–255

CONTRAST STRETCHING

Contrast Stretching — ยืดช่วงค่า

ภาพซีด = ค่าพิกเซลอยู่ในช่วงแคบ — ยืดให้เต็ม 0–255 เห็นความต่างชัดขึ้น

ก่อน-หลังยืดช่วง
ก่อน: ค่าอยู่แค่ 50–150 (ซีด)
↓
หลัง: ยืดเป็น 0–255

หลักการ

หาค่าต่ำสุด-สูงสุดของภาพ → map ใหม่: ค่าต่ำสุด → 0, ค่าสูงสุด → 255, ค่ากลางยืดตามสัดส่วน

ใช้เมื่อไร?

ภาพคอนทราสต์ต่ำ (ทุกค่าอยู่กลาง ๆ) — เช่น ภาพที่แสงแย่ ๆ ถ่ายกลางแจ้ง

เทคนิคสอบStretching = ยืดช่วงแคบให้กว้าง (50–150 → 0–255) เพิ่ม contrast

GAMMA (POWER-LAW)

Gamma Transformation — s = c·r^γ

Power-Law Transform — ยกกำลังค่าพิกเซลด้วย γ (gamma) เพื่อปรับโทนแสง

อ่านสูตร
rค่าพิกเซลอินพุต (normalize 0–1)
sค่าพิกเซลเอาต์พุต
cค่าคงที่ (ปกติ = 1)
γgamma — ตัวกำหนดผล (ยกกำลัง)
ทำไมต้อง normalize?ค่า 0–255 ยกกำลังแล้วใหญ่เกิน — ต้องหาร 255 ก่อน (ได้ 0–1) แล้วคูณกลับ

รูปร่างกราฟ

เส้นฟ้า γ<1 (ยกขึ้น) · ขาว γ=1 (เดิม) · ส้ม γ>1 (กดลง)

เทคนิคสอบs = c·r^γ · γ<1 สว่าง · γ=1 คงเดิม · γ>1 มืด

GAMMA VALUES

อ่านค่า γ — จำ 3 กรณี

γ ต่ำกว่า/เท่ากับ/มากกว่า 1 ให้ผลต่างกัน — นี่คือหัวใจของ Gamma

ค่า γผลต่อภาพตัวอย่างเหตุผล
γ < 1ภาพสว่างขึ้นγ = 0.5เศษส่วนยกกำลัง → ค่ามืดถูกดันขึ้น
γ = 1ภาพไม่เปลี่ยนγ = 1.0r^1 = r — ค่าเดิมทุกพิกเซล
γ > 1ภาพมืดลงγ = 2.2กำลัง > 1 → ค่าสว่างถูกกดลง

γ = 0.5

0.25^0.5 = 0.5 → ค่ามืด (0.25) สว่างขึ้นเป็น 0.5

γ = 1

0.5^1 = 0.5 → ไม่มีอะไรเปลี่ยน

γ = 2.2

0.75^2.2 ≈ 0.53 → ค่าสว่าง (0.75) มืดลง

เทคนิคสอบγ<1 = สว่าง (ใช้แก้ภาพมืด) · γ>1 = มืด (มาตรฐานจอ 2.2) — จำคู่ γ=0.5/2.2

GAMMA EXAMPLES

ตัวอย่าง γ = 0.5 และ γ = 2.2

ค่า gamma สองตัวที่เจอบ่อยสุด — จำไว้ว่าใช้เมื่อไร

γ = 0.5 — ใช้แก้ภาพมืด 
import cv2
import numpy as np

def gamma(img, g):
    inv = 1.0 / g
    table = np.array([((i / 255.0) ** inv) * 255
                      for i in range(256)]).astype("uint8")
    return cv2.LUT(img, table)

bright = gamma(img, 0.5)   # γ < 1 → สว่างขึ้น

γ = 0.5

ดันค่ามืดขึ้น → ภาพสว่าง เห็นรายละเอียดในเงา — เหมาะกับภาพถ่ายย้อนแสง

γ = 2.2

มาตรฐาน sRGB ของจอ — ใช้ตอนแสดงผล และใช้ "ลด" ความสว่างของภาพที่สว่างเกิน

เทคนิคสอบแก้ภาพมืด → γ = 0.5 · มาตรฐานจอ → γ = 2.2 · ไม่เปลี่ยน → γ = 1

LOG TRANSFORM

Logarithmic Transformation

s = c·log(1 + r) — log ยกค่ามืดขึ้นมาก แต่อยู่ใกล้เดิมเมื่อค่าสว่าง → เน้นรายละเอียดในเงา

ทำไม log ถึงช่วยเงามืด?
1ค่ามืด r=5 → log(6) ≈ 1.79 (เพิ่มขึ้น ~2.6 เท่า)
2ค่าสว่าง r=250 → log(251) ≈ 5.52 (เพิ่ม ~1.02 เท่า)
3ผล: ความต่างของเงามืดถูกขยาย — เห็นรายละเอียดที่เคยดำสนิท
+1 ใน log(1+r)กัน log(0) ที่ให้ค่า −∞ — ทำให้ค่าต่ำสุดเป็น log(1) = 0

เหมาะกับภาพแบบใด?

ภาพที่มี dynamic range กว้าง — สว่างจ้าและมืดสนิทในภาพเดียวกัน เช่น ถ่ายย้อนแสง

เทียบกับ Gamma

ทั้งคู่ช่วยเงามืด — Gamma ควบคุมด้วยตัวเดียว (γ) ปรับได้ละเอียดกว่า · Log ตายตัว

เทคนิคสอบLog = s = c·log(1+r) · เน้นรายละเอียดในเงามืด · dynamic range กว้าง

HISTOGRAM

Histogram คืออะไร?

กราฟนับจำนวนพิกเซลต่อระดับความเข้ม (0–255) — เห็นภาพรวมของความสว่างได้ในรูปเดียว

Histogram ของภาพตัวอย่าง
0 (ดำ)128255 (ขาว) 
# คำนวณด้วย OpenCV / Matplotlib
hist = cv2.calcHist([gray], [0], None, [256], [0, 256])
plt.hist(img.ravel(), bins=256)

อ่านยังไง?

แกน x = ค่าพิกเซล 0–255 · แกน y = จำนวนพิกเซล — แท่งสูง = มีพิกเซลเยอะที่ค่านั้น

บอกอะไรได้?

ภาพมืด/สว่าง/คอนทราสต์ต่ำ/สูง — ดู histogram ก่อนปรับภาพเสมอ

เทคนิคสอบHistogram = การกระจายพิกเซลต่อระดับ 0–255 · calcHist หรือ plt.hist

READING HISTOGRAMS

อ่าน Histogram — 3 รูปแบบ

จำ 3 ลักษณะของ histogram ↔ สภาพภาพ — ใช้ตอบโจทย์วิเคราะห์ภาพได้ทันที

ภาพมืด

แท่งเบียดซ้าย — พิกเซลส่วนใหญ่ค่าต่ำ

ภาพสว่างเกิน

แท่งเบียดขวา — พิกเซลส่วนใหญ่ค่าสูง

คอนทราสต์ต่ำ

แท่งรวมกลางแคบ ๆ — ไม่มีดำ/ขาวจริง

เทคนิคสอบซ้าย = มืด · ขวา = สว่าง · กลางแคบ = ซีด (contrast ต่ำ) · กระจายเต็ม = ดี

HISTOGRAM EQUALIZATION

Histogram Equalization

กระจาย histogram ที่เบียดกันให้ "แบน" ครอบทั้ง 0–255 → คอนทราสต์ดีขึ้นอัตโนมัติ

ก่อน → หลัง Equalization

ก่อน — เบียดกลาง

→

หลัง — กระจายทั่ว

ทำงานยังไง?

คำนวณ cumulative (สะสม) ของ histogram → สร้างตารางแปลงค่าที่กระจายพิกเซลเท่า ๆ กันทั้งช่วง

ข้อระวัง

ภาพที่ noise เยอะ → equalize ทั้งภาพอาจทำให้ noise โผล่ชัดขึ้น (แก้ด้วย CLAHE)

เทคนิคสอบEqualization = กระจาย histogram ให้ทั่ว 0–255 · ภาพซีด/มืดให้ลองก่อน

OPENCV CODE

cv2.equalizeHist() — โค้ด

หนึ่งบรรทัดจบ — แต่จำไว้ว่าใช้ได้กับ ภาพ 1 ช่อง (grayscale)

โค้ด grayscale 
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
eq = cv2.equalizeHist(gray)   # 1 ช่องเท่านั้น

plt.hist(gray.ravel(), bins=256)   # ก่อน
plt.hist(eq.ravel(), bins=256)     # หลัง

ภาพสีทำยังไง?

แปลงเป็น YUV → equalize ช่อง Y (ความสว่าง) → แปลงกลับ — ทำที่ RGB ตรง ๆ จะสีเพี้ยน

yuv = cv2.cvtColor(img, cv2.COLOR_BGR2YUV)
yuv[:, :, 0] = cv2.equalizeHist(yuv[:, :, 0])
res = cv2.cvtColor(yuv, cv2.COLOR_YUV2BGR)
เทคนิคสอบequalizeHist รับภาพ 1 ช่อง · ภาพสีทำที่ช่อง Y (YUV) แล้วแปลงกลับ

CLAHE

CLAHE — Equalization แบบ Local

Contrast Limited Adaptive Histogram Equalization — แบ่งภาพเป็นบล็อกเล็ก ๆ แล้ว equalize ทีละบล็อก

แบ่งภาพเป็นบล็อก (tile)

แต่ละบล็อก equalize ด้วย histogram ของตัวเอง

โค้ด

clahe = cv2.createCLAHE(clipLimit=2.0,
                        tileGridSize=(8, 8))
res = clahe.apply(gray)

ดีกว่า equalize ทั่วไปยังไง?

ไม่ทำให้ noise โผล่ทั้งภาพ — เพราะจำกัด contrast ต่อบล็อก (clipLimit) ปรับตามแสงเฉพาะที่

เทคนิคสอบCLAHE = local (บล็อกเล็ก) + จำกัด contrast · เหมาะภาพแสงไม่สม่ำเสมอ

COMPARISON

เปรียบเทียบ 3 วิธี

Histogram Equalization vs CLAHE — และวิธีปรับแสงอื่น ๆ ที่เรียนมา

วิธีหลักการเหมาะกับข้อเสีย
convertScaleAbsalpha × pixel + betaปรับสว่าง/คอนทราสต์ทั่วภาพปรับด้วยมือ ต้องเดาค่า
equalizeHistกระจาย histogram ทั้งภาพ (global)ภาพซีด/มืดทั่วไปnoise อาจโผล่ชัด
CLAHEequalize แบบบล็อกเล็ก + จำกัด contrastแสงไม่สม่ำเสมอ, ภาพมี noiseช้ากว่า, มี parameter
เลือกยังไง?ภาพซีดปกติ → equalizeHist · ภาพแสงไม่เท่ากัน/มี noise → CLAHE · อยากควบคุมเอง → convertScaleAbs
